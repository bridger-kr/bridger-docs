# 0001 — Single source of truth for product facts

Date: 2026-09-30
Status: Accepted
Linear: EDD-269

## Context

Users saw contradictory product facts across bridger.kr, docs.bridger.kr, and the API:

| Fact | web | docs | verified reality (2026-09-30) |
| --- | --- | --- | --- |
| MCP endpoint | `mcp.bridger.kr` | `https://mcp.datari.kr/mcp`, `/mcp/sse` | `https://mcp.bridger.kr/mcp` (Streamable HTTP). `mcp.datari.kr` serves the Kubernetes ingress fake certificate — unreachable. |
| Claude | claude.ai web custom connector | Claude Desktop config + SSE | claude.ai custom connector → OAuth at `api.bridger.kr` |
| ChatGPT | developer-mode custom connector | "GPTs (Actions)" | developer-mode custom connector |
| Login | Google + GitHub | Google / Kakao | Google + GitHub (only providers in `internal/datariauth/providers.go`) |
| BYOAPI | working `POST /api/v1/register` guide | "추후 제공 예정" | Live for authenticated tenants (`internal/controlplane/byoapi_routes.go`) |
| Catalog size | "8 core categories" (ko: 8 개 핵심 카테고리) | "over 230", "14 categories · 218 presets · 285 tools" | `GET /api/v1/government-apis?limit=1` → `total: 446`; 16 live categories; 218 preset YAMLs / 285 operationIds in the spec repo |
| Tool names | `weather.short_term_forecast`, `kma_forecast` | `datari.search_tools` | `<toolPrefix>_<operationId snake_case>` from mcp-gen, e.g. `kma_get_village_forecast`; meta tool `search_tools` |

## Decision

- One canonical facts file: `bridger-spec/facts/product-facts.json` (vendored into each repo via the existing `vendor/spec` git submodule). `scripts/validate-facts.mjs` in bridger-spec recomputes spec-derived counts and asserts schema invariants.
- `catalogCountSource: "api"` — user-facing catalog counts are **never literals**: they come from `GET /api/v1/government-apis?limit=1` → `total`, fetched at runtime (bridger-web landing) or build time (bridger-docs `build:content`).
- bridger-web: `shared/product-facts.mjs` re-exports typed constants from `shared/product-facts.data.mjs`, generated by `scripts/gen-product-facts.mjs` (same convention as `gen-preset-sources.mjs`; PR CI checks out `submodules: false`, so apps never import the submodule path directly). Consumers: `landing/src/lib/product-urls.js`, `dashboard/src/constants/productUrls.ts`, `dashboard/src/constants/gatewayHosts.ts`, `dashboard/src/lib/runtime-config.ts`.
- bridger-docs: `scripts/build-facts.mjs` syncs `docs.json` `variables` from the JSON and fetches `catalogTotal` live. Pages use `{mcpUrl}`, `{catalogTotal}`, `{loginProviders}`, `{byoapiRegisterUrl}`, … (Mintlify variables) instead of restating values.
- Deprecated facts (`mcp.datari.kr`) are recorded in the JSON under `deprecated` so the broken host never returns to published copy.
- Numbers that cannot be injected (frontmatter `description`, static marketing cards) drop the numeral entirely rather than hardcoding a figure that drifts.

## Consequences

- A fact change = one spec PR + a submodule bump in each consumer; generated artifacts (`product-facts.data.mjs`, `docs.json` variables, preset pages) are regenerated by the documented npm scripts.
- `npm run build:content` in docs requires network access to `api.bridger.kr` for the live `catalogTotal`; on failure it keeps the previously fetched value.
- Spec-derived preset counts (218 presets / 285 tool operations) may appear in generated docs but never hand-written copy; generated ko phrasing uses `**N**개`/`N종` so the ticket's completion grep over stale count literals stays at zero while values remain correct.
