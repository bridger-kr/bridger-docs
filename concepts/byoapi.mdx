DATA BRIDGE의 **BYOAPI(Bring Your Own API)** 는 OpenAPI 스펙만 가지고 있다면 어떤 API든
**별도 컨테이너 빌드/배포 없이** DATA BRIDGE Gateway의 MCP 도구로 즉시 등록되는 기능입니다.

## 핵심 아이디어 — 배포가 아니라 등록

<CardGroup cols={2}>
  <Card title="기존 방식" icon="container-storage">
    API 한 개당 컨테이너 한 개를 빌드·배포·운영. 비용·관리 모두 폭증.
  </Card>
  <Card title="DATA BRIDGE BYOAPI" icon="bolt">
    Tool 정의만 DB에 등록. 단일 Gateway가 ID로 라우팅 → 수 초 내 완료.
  </Card>
</CardGroup>

```text
하나의 DATA BRIDGE Gateway (mcp.datari.kr)
  ├─ getweatherforecast        (server id: weather/forecast)
  ├─ getbusarrival             (server id: transportation/bus-arrival)
  ├─ getmycustomdata           (server id: custom/my-custom-api)
  ├─ getinternalcrm            (server id: custom/internal-crm)
  └─ ... 230+ tools
```

## Tool 이름과 서버 ID 체계

각 프리셋·BYOAPI는 하나의 **서버(MCP 그룹)** 로 등록되며, 서버는 1개 이상의 도구를 가집니다.

- **도구 이름**(`tools[].name`)은 OpenAPI `operationId`에서 파생됩니다. 소문자로 변환하고 영숫자가 아닌 문자는 제거합니다. 예: `getUltraSrtFcst` → `getultrashortcast`.
- **서버 ID**(`servers[].id`)는 `{category}/{name}` 형식으로 그룹을 구분합니다. 예: `weather/ultra-shortcast`, `realestate/apt-trade`.

| 구분 | 서버 ID 예시 | 도구 이름 예시 |
| --- | --- | --- |
| 공식 프리셋 | `weather/forecast` | `getweatherforecast` |
| 공공데이터 카테고리 | `realestate/apt-trade` | `getapttrade` |
| 사용자 커스텀(BYOAPI) | `custom/my-petstore` | `listpets`, `getpetbyid` |

**규칙**

- 도구 이름은 `tools/list` 응답의 `name`으로 그대로 `tools/call`에 사용합니다.
- BYOAPI 등록 시 `category`를 지정하지 않으면 기본값은 `custom`입니다.
- 서버 ID는 카테고리와 이름 조합으로 Gateway 내에서 unique합니다.

## 등록 파이프라인

<Steps>
  <Step title="Ingestion">
    OpenAPI 스펙을 URL · 파일 업로드 · 인라인 텍스트 중 하나로 입력합니다.
  </Step>
  <Step title="Validation">
    스펙 유효성·보안 스캔·MCP 변환 적합성 점수를 계산합니다.
  </Step>
  <Step title="Generation">
    OpenAPI `paths`를 MCP Tool 정의로 변환합니다 (`name`, `description`, `inputSchema`).
  </Step>
  <Step title="Registration">
    Tool Registry DB에 등록 — **컨테이너 배포 없음**.
  </Step>
  <Step title="Ready">
    즉시 `mcp.datari.kr/mcp`의 `tools/list`에 노출, `tools/call` 시 런타임 프록시로 upstream 호출.
  </Step>
</Steps>

## 등록 후 동작

| 단계 | 설명 |
| --- | --- |
| 도구 노출 | 등록된 도구는 `tools/list` 응답에 포함됩니다. |
| 호출 라우팅 | `tools/call` 요청의 도구 ID를 기준으로 대상 API를 선택합니다. |
| 인증 주입 | 저장된 인증 설정에 따라 upstream 요청에 필요한 헤더나 토큰을 주입합니다. |
| 응답 정규화 | upstream 응답을 MCP 클라이언트가 읽기 쉬운 형태로 반환합니다. |

## tools/list 응답 예시

```json
{
  "tools": [
    {
      "name": "getweatherforecast",
      "description": "기상청 단기예보 — 위치 기반 날씨 정보",
      "inputSchema": {
        "type": "object",
        "properties": {
          "nx": { "type": "integer", "description": "예보지점 X 좌표" },
          "ny": { "type": "integer", "description": "예보지점 Y 좌표" }
        },
        "required": ["nx", "ny"]
      },
      "annotations": {
        "readOnlyHint": true,
        "destructiveHint": false,
        "openWorldHint": false
      }
    },
    {
      "name": "listpets",
      "description": "List all pets in the store",
      "inputSchema": { /* ... */ }
    }
  ]
}
```

## 데이터 모델 (요약)

```sql
CREATE TABLE tool_registrations (
  id            UUID PRIMARY KEY,
  owner_id      UUID NOT NULL REFERENCES users(id),
  server_id     VARCHAR(128) NOT NULL UNIQUE,   -- {category}/{name}, 예: weather/forecast
  display_name  VARCHAR(256),
  description   TEXT,
  category      VARCHAR(64),

  source_type   VARCHAR(16),     -- preset | byoapi | manual
  source_spec   TEXT,            -- 원본 OpenAPI (압축)
  spec_hash     VARCHAR(64),     -- SHA-256

  upstream_base_url VARCHAR(512),
  upstream_paths    JSONB,       -- [{method, path, operationId, inputSchema, ...}]
  auth_config       JSONB        -- {type, header, tokenEndpoint, ...}
);
```

세부 등록 화면과 필드 설명은 어드민 대시보드의 BYOAPI 등록 플로우에서 확인할 수 있습니다.
