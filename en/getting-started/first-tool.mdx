This page shows what request returns what response right after you connect to the Bridger Gateway.
Pick one tool and trace the input → output flow; from then on, you can call any tool with the same
pattern.

## Prerequisites

- [API key issued](/en/guides/api-keys)
- Key stored in the `BRIDGER_API_KEY` environment variable

```bash
export BRIDGER_API_KEY="dk_live_..."
```

## 1. List registered tools

`tools/list` returns the **metadata of every MCP tool** loaded into Bridger (`name`, `description`,
`inputSchema`).

<CodeGroup>
  ```bash cURL
  curl -X POST https://mcp.bridger.kr/mcp?activation=all \
    -H "x-api-key: $BRIDGER_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
  ```

  ```javascript Node.js
  const res = await fetch("https://mcp.bridger.kr/mcp?activation=all", {
    method: "POST",
    headers: {
      "x-api-key": process.env.BRIDGER_API_KEY,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      jsonrpc: "2.0",
      id: 1,
      method: "tools/list",
    }),
  });
  console.log(await res.json());
  ```

  ```python Python
  import os, requests
  r = requests.post(
      "https://mcp.bridger.kr/mcp?activation=all",
      headers={
          "x-api-key": os.environ["BRIDGER_API_KEY"],
          "Content-Type": "application/json",
      },
      json={"jsonrpc": "2.0", "id": 1, "method": "tools/list"},
  )
  print(r.json())
  ```
</CodeGroup>

The response includes tools with the following structure.

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "tools": [
      {
        "name": "getultrashortcast",
        "description": "KMA ultra-short-term forecast — data.go.kr OpenAPI",
        "inputSchema": {
          "type": "object",
          "properties": {
            "ServiceKey": { "type": "string" },
            "base_date": { "type": "string" },
            "base_time": { "type": "string" },
            "nx": { "type": "integer" },
            "ny": { "type": "integer" },
            "pageNo": { "type": "integer" },
            "numOfRows": { "type": "integer" }
          },
          "required": ["ServiceKey", "pageNo", "numOfRows", "base_date", "base_time", "nx", "ny"]
        }
      }
    ]
  }
}
```

## 2. Run a tool

Pick one tool and run it with `tools/call`. The example is an ultra-short-term forecast for Seoul.

```bash
curl -X POST https://mcp.bridger.kr/mcp?activation=all \
  -H "x-api-key: $BRIDGER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/call",
    "params": {
      "name": "getultrashortcast",
      "arguments": {
        "ServiceKey": "YOUR_DATA_GO_KR_SERVICE_KEY",
        "pageNo": 1,
        "numOfRows": 10,
        "base_date": "20261016",
        "base_time": "0630",
        "nx": 61,
        "ny": 126
      }
    }
  }'
```

Use the exact name and inputSchema returned by `tools/list`. Dates/times are KST; replace the example with a recent forecast issue time. `ServiceKey` is your public-data provider key, separate from `BRIDGER_API_KEY`. If your configured provider credential is injected by the gateway, follow that credential setup instead of embedding a key.

## 3. Receive real-time events over SSE

For long-running tools or streaming responses, subscribe to the SSE endpoint (`/mcp`).

```bash
curl -N https://mcp.bridger.kr/mcp?activation=all \
  -H "x-api-key: $BRIDGER_API_KEY"
```

A `gateway/toolResult` event is delivered to your client for each tool execution.
