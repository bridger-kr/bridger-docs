## Base URL

| Host | Routes | Purpose |
| --- | --- | --- |
| `https://mcp.bridger.kr` | `/mcp`, `/health` | MCP JSON-RPC, SSE, health |
| `https://api.bridger.kr` | `/api/v1/government-apis` | Public-data API catalog (REST) |
| `https://api.bridger.kr` | `/registry/servers`, `/registry/tools` | Deprecated; always empty |

## Authentication in one line

Every protected endpoint accepts one of the following two headers.

```http
x-api-key: dk_live_...
Authorization: Bearer dk_live_...
```

See [Authentication](/en/api-reference/authentication) for the full auth flow, OAuth, and error codes.

## Common error format

Authentication failures are not returned as JSON. Calling a protected endpoint
with an invalid key answers `401 Unauthorized` with a `text/plain` body and a
`WWW-Authenticate` challenge.

```http
HTTP/1.1 401 Unauthorized
Content-Type: text/plain; charset=utf-8
WWW-Authenticate: Bearer error="invalid_token", resource_metadata="https://mcp.bridger.kr/.well-known/oauth-protected-resource/mcp"

invalid_token
```

A token lacking the required scope is rejected with `403 Forbidden` and
`Bearer error="insufficient_scope", resource_metadata="...", scope="..."`. See
[Authentication](/en/api-reference/authentication) for the full format.

The JSON-RPC endpoint (`/mcp`) returns a [JSON-RPC 2.0 error object](https://www.jsonrpc.org/specification#error_object).

| Code | Meaning |
| --- | --- |
| `-32600` | Invalid JSON-RPC request |
| `-32601` | Method not found |
| `-32602` | Invalid params (e.g. missing tool name) |
| `-32000` | Internal gateway error |

## Content Types

- Request/response: `application/json`
- SSE stream: `text/event-stream`
