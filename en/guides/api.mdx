title: "Call directly via REST / MCP SDK"
description: "Developer guide for calling the Bridger Gateway via REST, MCP SDK, and BYOAPI without an AI client."
---

Even without Claude or ChatGPT, the Bridger Gateway can be called directly via REST and the standard MCP SDK.

Use `tools/list` names and schemas exactly. Set `DATA_GO_KR_SERVICE_KEY` to your public-data provider key (separate from the Bridger key), and replace the sample date/time with a recent forecast issue time in KST.

<Steps>
  <Step title="Issue an API key">
    Issue an API key on the **Bridger API keys** page in the [portal](https://portal.bridger.kr).
    See the [API key guide](/en/guides/api-keys) as well.
  </Step>

  <Step title="Call the REST API">
    Call the standard REST endpoints.

    <CodeGroup>
      ```bash List tools (registered tools)
      curl -X GET https://api.bridger.kr/api/v1/tools \
        -H "Authorization: Bearer YOUR_API_KEY" \
        -H "Content-Type: application/json"
      ```

      ```bash Get a single tool
      curl -X GET https://api.bridger.kr/api/v1/tools/TOOL_ID \
        -H "Authorization: Bearer YOUR_API_KEY"
      ```
    </CodeGroup>

    <Note>
      REST is for **listing, retrieving, registering, and managing** tools. Tool **execution** is done
      via MCP JSON-RPC `tools/call` (`POST /mcp`). See the MCP SDK examples below.
    </Note>
  </Step>

  <Step title="MCP SDK integration (Node.js)">
    To integrate programmatically, use the official MCP SDK.

    ```bash Install
    npm install @modelcontextprotocol/sdk
    ```

    ```javascript client.js
    import { Client } from "@modelcontextprotocol/sdk/client/index.js";
    import { StreamableHTTPClientTransport } from "@modelcontextprotocol/sdk/client/streamableHttp.js";

    const transport = new StreamableHTTPClientTransport(
      new URL("https://mcp.bridger.kr/mcp?activation=all"),
      {
        requestInit: {
          headers: {
            Authorization: "Bearer YOUR_API_KEY",
          },
        },
      }
    );

    const client = new Client({
      name: "my-app",
      version: "1.0.0",
    });

    await client.connect(transport);

    // activation=all returns the full catalog of names and input schemas.
    const tools = await client.listTools();
    console.log(tools);

    // Run a tool
    const result = await client.callTool({
      name: "getvillageforecast",
      arguments: {
        ServiceKey: process.env.DATA_GO_KR_SERVICE_KEY,
        pageNo: 1,
        numOfRows: 10,
        base_date: "20261016",
        base_time: "0500",
        nx: 60,
        ny: 127,
      },
    });
    console.log(result);
    ```
  </Step>

  <Step title="MCP SDK integration (Python)">
    You can implement the same flow in Python.

    ```bash Install
    pip install mcp
    ```

    ```python client.py
    from mcp import ClientSession
    from mcp.client.streamable_http import streamablehttp_client
    import asyncio
    import os

    async def main():
        headers = {"Authorization": "Bearer YOUR_API_KEY"}

        async with streamablehttp_client(
            "https://mcp.bridger.kr/mcp?activation=all",
            headers=headers,
        ) as (read, write, _get_session_id):
            async with ClientSession(read, write) as session:
                await session.initialize()

                tools = await session.list_tools()
                print(tools)

                result = await session.call_tool(
                    "getvillageforecast",
                    arguments={
                        "ServiceKey": os.environ["DATA_GO_KR_SERVICE_KEY"],
                        "pageNo": 1,
                        "numOfRows": 10,
                        "base_date": "20261016",
                        "base_time": "0500",
                        "nx": 60,
                        "ny": 127,
                    },
                )
                print(result)

    asyncio.run(main())
    ```
  </Step>

  <Step title="BYOAPI — register your own API">
    A REST API with an OpenAPI spec can be registered as a Bridger tool.
    See the [BYOAPI concept doc](/en/concepts/byoapi) for the full flow.

    ```bash Register an API
    curl -X POST https://api.bridger.kr/api/v1/register \
      -H "Authorization: Bearer YOUR_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "spec_url": "https://api.example.com/openapi.json",
        "name": "my-service",
        "auth": { "type": "bearer", "token": "SERVICE_API_KEY" },
        "visibility": "private"
      }'
    ```

    <Note>
      Either `spec_url` (remote spec) or `spec_raw` (inline spec string) plus `name` is required.
      Registration is processed asynchronously and the response returns a `job_id`.
      Check progress with `GET /api/v1/register/:id/status`.
    </Note>
  </Step>
</Steps>

## API reference summary

| Method | Path | Description |
| ------ | ----- | ---- |
| `GET`  | `/api/v1/tools`               | List registered tools |
| `GET`  | `/api/v1/tools/:toolId`       | Get a single tool |
| `POST` | `/api/v1/register`            | BYOAPI registration (`{spec_url\|spec_raw, name, auth, visibility}`) |
| `GET`  | `/api/v1/register/:id/status` | BYOAPI registration job status |
| `GET`  | `/registry/servers`           | Preset server (MCP group) catalog |
| `GET`  | `/registry/tools`             | Flattened tool list |
| `GET`  | `/mcp`                    | MCP SSE event stream |
| `POST` | `/mcp`                        | JSON-RPC (`tools/list`, `tools/call`) — tool execution |

See the [API Reference](/en/api-reference/introduction) tab for the full spec.
