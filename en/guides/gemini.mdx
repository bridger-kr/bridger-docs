title: "Connect to Gemini"
description: "How to use Bridger MCP from Gemini CLI and Gemini Enterprise."
---

You can connect Bridger as an MCP server in **Gemini CLI** (the developer terminal
tool) and **Gemini Enterprise** (organization-wide).

<Note>
  **The consumer Gemini app** (gemini.google.com and the mobile apps) is not a
  connection target. Its custom MCP support ("Custom apps for Spark") is limited
  to US-based, English-language personal accounts, so the menu does not appear on
  Korean accounts — use Gemini CLI or Gemini Enterprise below instead.
</Note>

## Gemini CLI

Register the MCP server in `~/.gemini/settings.json`:

```json ~/.gemini/settings.json
{
  "mcpServers": {
    "bridger": {
      "httpUrl": "https://mcp.bridger.kr/mcp"
    }
  }
}
```

Or register it with a single command:

```bash
gemini mcp add --transport http bridger https://mcp.bridger.kr/mcp
```

On first use, your browser opens the Bridger sign-in (Google · GitHub) and consent
screen. Inside the CLI, type `/mcp` to see server status and the auth menu.

<Tip>
  **One-line CLI extension install is coming soon.** Once published, you'll be able to run
  `gemini extensions install https://github.com/bridger-kr/bridger-gemini-extension`.
  Until then, use the `settings.json` method above.
</Tip>

## Gemini Enterprise

In Gemini Enterprise, an admin registers a custom MCP connector. Enter these values
in the connector setup screen:

| Field | Value |
| --- | --- |
| MCP server URL | `https://mcp.bridger.kr/mcp` |
| Transport | Streamable HTTP |
| Authorization URL | `https://api.bridger.kr/oauth/authorize` |
| Token URL | `https://api.bridger.kr/oauth/token` |
| Client ID / Client secret | Request from Bridger ([hello@bridger.kr](mailto:hello@bridger.kr)) |
| Scopes (space-separated) | `tools:read tools:execute offline_access` |
| PKCE | Enabled — Bridger accepts **S256** only |
| Redirect URI | `https://vertexaisearch.cloud.google.com/oauth-redirect` (fixed by Google) |

<Note>
  Gemini Enterprise doesn't support dynamic client registration (DCR), so it needs a
  pre-registered, non-expiring confidential client. Request one for the redirect URI above and
  Bridger will issue the client ID and secret. The secret is shared once — store it securely.
</Note>

| Scope | Meaning |
| --- | --- |
| `tools:read` | List tools (`tools/list`) |
| `tools:execute` | Run tools (`tools/call`) |
| `offline_access` | Issue refresh tokens to keep the connection alive |

<Tip>
  Gemini Enterprise allows at most 100 enabled actions per connector. Bridger trims the tool list
  for Gemini Enterprise connections to stay within that cap. After saving, enable the actions
  you need in the connector's **Actions** list.
</Tip>

## Troubleshooting

<AccordionGroup>
  <Accordion title="The server doesn't show up in Gemini CLI">
    Check the JSON syntax and `mcpServers` key placement in `~/.gemini/settings.json`,
    then run `gemini mcp list` to confirm it's registered.
  </Accordion>
  <Accordion title="The auth browser doesn't open">
    In the CLI, select `bridger` under `/mcp` and retry authentication. On headless
    environments, create the settings file on a machine with a browser first.
  </Accordion>
  <Accordion title="Enterprise authorization fails with invalid_redirect_uri / invalid_target">
    Make sure the issued client's redirect exactly matches
    `https://vertexaisearch.cloud.google.com/oauth-redirect`. The `resource` parameter is
    optional; if sent, it must exactly equal `https://mcp.bridger.kr/mcp`.
  </Accordion>
  <Accordion title="Enterprise shows a PKCE error">
    Enable PKCE in the connector settings with method `S256`. Plain PKCE or no PKCE is not
    supported.
  </Accordion>
  <Accordion title="Some tools won't run">
    Some public-data APIs need your own service key. Add it under **My service key** in the
    [Dashboard](https://portal.bridger.kr) to enable them.
  </Accordion>
  <Accordion title="Still not working?">
    Contact us at [hello@bridger.kr](mailto:hello@bridger.kr) or via Channel Talk.
  </Accordion>
</AccordionGroup>
