<Warning>Charging data covers the Suwon listing only. Distance-ranked recommendations, live charger availability and nationwide coverage are not provided.</Warning>

## 1. Start with a question like this

When a product team or automation partner runs outdoor plans in a Korean region, questions look like this:

- "What's today's weather for Yeongtong-gu in Suwon?"
- "Show the current air-quality state for Suwon."
- "List EV charging stations in Suwon."

Combined questions ("Weather, air quality and EV charging for Suwon today") work too; the app splits them into tool calls in the order region → weather → air quality → charging.

## 2. Which tools run

The tools below serve the examples above. Presets and tools are listed in each catalog.

| Component | Preset · tool | Note |
| --- | --- | --- |
| Location | `resolve_location` | Normalizes a region name / coordinates into a weather grid and administrative codes. It does not automatically pick an air-monitoring station. See [Korean data](/en/concepts/korean-data) |
| Weather | `weather/village-forecast` · `getVillageForecast` in the [weather catalog](/en/presets/weather) | Village forecast; works with grid coordinates (nx·ny) and issue date/time |
| Air quality | `environment/air-quality-realtime` · `getAirQualityRealtimeByStation` in the [environment catalog](/en/presets/environment) | Station-level realtime data |
| Charging | `transportation/ev-charging` · `getEvCharging` in the [transportation catalog](/en/presets/transportation) | **Suwon** data only |

Ambiguous place names and wrong coordinates cannot resolve until the target is
specific. In a developer environment you can call the tools directly with
`tools/list` · `tools/call` as shown in the [first tool guide](/en/getting-started/first-tool).

## 3. How to read the answer

| Component | How to read it |
| --- | --- |
| Weather | It is a forecast. Read the issue time and the forecast target time separately; do not confuse it with observations |
| Air quality | Station-level values. Check the measurement time and station; a single station is not the whole region. Missing measurements stay empty |
| Charging | A Suwon station registry. Addresses and coordinates exist, but that does not mean a live charger or distance-ranked results — proximity needs separate coordinate/distance computation |
| Location | Normalized administrative codes / weather grid, not a street-address verification result |

For a combined question that comes back only partially, read the missing reason:
outside-Suwon charging, missing measurements or forecasts not yet issued just lead to nothing yet. Follow up with the matching tool.

## Boundaries of this task

- Provider and key requirements are shown in the catalog tables ([weather · KMA](https://www.data.go.kr/data/15084084/openapi.do), [air quality · AirKorea](https://www.data.go.kr/data/15073861/openapi.do), [charging · Suwon](https://www.data.go.kr/data/15144026/openapi.do)); key problems start at the [API keys guide](/en/guides/api-keys).
- Observation/measurement times and forecast issue times are set by the provider and may differ from the HTTP response time.
- Recommendations, reservations, medical judgments and route optimization are out of scope; answers reorganize the provider data only.
