## Actual remediation

[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) has no patched official braces release (latest 3.0.3). Every braces consumer now resolves to the exact npm alias `npm:@bleedingdev/braces@3.0.4`. This is a third-party security backport, not an upstream release. The lockfile pins its tarball and SHA-512 integrity. Its registry metadata includes npm/SLSA provenance linked to https://github.com/ultramodernjs/ultramodern.js/tree/main/scripts/ultramodern-supply.

The published tarball was compared with official braces 3.0.3: runtime changes add `MAX_AST_DEPTH = 100`, parser checks for both brace and parenthesis nesting, and independent depth checks in compile/expand/stringify for direct AST callers. There are no new runtime dependencies or install scripts; fill-range remains `^7.1.1`. Normal expansion and regex compilation retain the upstream implementation. Deep input now raises a deliberate SyntaxError before stack exhaustion. This deliberately limits previously accepted extreme nesting.

`npm run test:dependency-security` discovers every installed braces path from the lockfile, verifies the replacement identity/version, tests normal expansion/ranges/compilation/stringification, and rejects balanced/unbalanced/parenthesized deep input and manually constructed deep ASTs. CI runs this regression in addition to every existing gate. Audit severity, registry advisories, validation commands, and CI gates are unchanged. No ignore list, audit suppression, or dependency downgrade is used.

The third-party fork adds a maintenance dependency: re-review any future update and remove the override only after an official fixed release is available and the regression passes. A clean advisory result by itself does not prove a fork secure; the source comparison and exploit regression are the remediation evidence.

## Remaining YAML3 chain

The CLI stays exactly `mintlify@4.2.942`. The current baseline differs from the issue's historical 12 high: today's matching baseline is 9 high / 7 moderate. After removing high severity propagation, 11 packages are classified moderate; this is severity reclassification of existing parent paths, not a new YAML dependency.

Mintlify common → `front-matter@4.0.2` → `js-yaml@3.15.2` → `argparse@1.0.10` → `sprintf-js@1.0.3` remains affected by [GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c). The latest sprintf-js 1.1.3 is also affected. Front-matter's latest release still requires YAML3 and calls its `safeLoad` API; YAML4 removed that API, so forcing YAML4 underneath it breaks parsing. Upstream must migrate front-matter to a YAML4-compatible parser/API (or Mintlify replace it). Replacing the pinned CLI is outside the allowed constraint. We retain and document this unresolved moderate chain; full npm audit still exits 1. Production audit remains clear. No claim of complete vulnerability elimination.
