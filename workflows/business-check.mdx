<Warning>작업 설계와 오프라인 예시입니다. 실제 기관 응답·고객 채택·법적 승인 증거가 아니며, 신용·사기 판정이나 상세 주소 검증을 제공하지 않습니다.</Warning>

## 누구를 위한 작업인가

거래처 등록을 반복 처리하는 제품팀과 자동화 파트너가 대상입니다.
담당자가 적법하게 보유한 사업자등록번호로 국세청 사업자 상태를 조회하고,
지역 코드가 필요한 경우 사용자가 별도로 확인한 행정 코드·기상 격자를 함께 기록합니다.
폐업 여부 등의 상태는 신뢰도 점수나 거래 승인 결론이 아닙니다. 최종 판단은 담당자가 합니다.

## 입력과 채택 가능한 결과

| 항목 | 계약 |
| --- | --- |
| 필수 입력 | 사업자등록번호. 운영자가 목적·권한을 확인한 후 실행 경로에서만 전달 |
| 선택 입력 | 사용자가 별도로 확인한 지역 코드와 출처·기준 시점. 요청하지 않은 지역 정보는 필수 결과에서 제외 |
| 채택 가능한 출력 | 기관의 사업자 상태와 조회 기준 시각, 출처, 요청한 지역 코드, 누락 사유를 함께 읽고 담당자가 업무에 사용했다고 명시 |
| 지원하지 않는 판단 | 신용·사기·실소유자·신원 검증, 도로명/건물/우편 주소 검증, 자동 거래 승인 |
| 개인정보 경계 | 번호·주소·키·원문 질의는 분석 이벤트와 공개 예시에 넣지 않음. 운영 로그·보존·삭제 범위는 별도 검토 |

<Note>
  **준비 중:** `resolve_location`은 운영 MCP에 배포되지 않아 현재 호출할 수 없습니다.
  지역명·좌표의 자동 정규화는 이 작업의 실행 단계에서 제외합니다.
  지역 코드를 별도로 확인할 수 없으면 제안된 결과 계약에 누락 사유를 기록하세요.
</Note>

## 기존 도구와 연결

1. [AI 연결 가이드](/guides/claude)와 [첫 도구 실행](/getting-started/first-tool)의 인증·활성화 경로를 사용합니다.
2. [민원 프리셋](/presets/civil)의 `civil/business-registration`에서 `getBusinessRegistrationStatus`를 확인합니다.
3. 원본 응답에 포함된 상태·조회 기준 시각을 보존하고 상태 확인과 정보 일치 확인을 구분합니다.
4. 기존 사업자 정보 확인 위젯은 `validateBusinessRegistration`용입니다. 추가 입력의 권한과 목적이 확인된 경우에만 사용하며, 상태 조회 결과나 신용 판정을 대신하지 않습니다.
5. 성공 결과를 얻는 것과 업무 채택은 별개입니다. 사용자의 명시적인 채택 전에는 퍼널의 `adopted`를 기록하지 않습니다.

키가 없거나 활성화가 끝나지 않았으면 실행하지 않습니다. 공개 문서를 읽거나 카탈로그에서 도구를 선택한 것은 작업 성공이 아닙니다.

## 출처·시점·권한·비용

문서 검토일은 2026-10-10입니다. 아래는 저장소 메타데이터 검토이며 기관에 실시간 요청한 결과가 아닙니다.

| 소스 | 기준과 제한 |
| --- | --- |
| [국세청 사업자등록정보](/presets/civil) | [공공데이터포털 등록 페이지](https://www.data.go.kr/data/15081808/openapi.do). 상태 조회와 정보 진위 확인을 구분 |
| 지역 코드 (선택) | 사용자가 별도로 확인한 값. 출처와 기준 시점을 함께 기록하며 자동 정규화 결과로 표시하지 않음 |
| `source` / `asOf` | 출처와 기관 응답의 기준 시각을 전달. 기준 시각 불명은 현재 시각으로 꾸미지 않고 `missing_asof` 처리 |
| 권한 | 기관 이용조건·서비스 키 신청/승인·재배포 범위는 담당자 확인 전 미검토. 브릿저 API 키의 권한과 기관 승인도 별개 |
| 비용 | 제공 기관의 쿼터, 내 인증키 또는 관리 키 사용 가능 여부, 브릿저 요금/지원 범위를 실행 전에 확인. 무료·무제한 보장 없음 |

지역 코드 입력의 기준 시점은 사업자 상태의 기준 시각이 아닙니다.
유효한 상태라도 오래된 자료이면 사용 목적별로 합의한 최신성 기준을 통과해야 합니다.
기관 문서·권리·키와 승인된 실제 smoke 확인 전에는 운영 준비 완료를 주장하지 않습니다.

## 결과와 누락 처리

아래는 이 작업의 **제안된 정규화 계약**이며 현재 MCP의 원문 응답 스키마를 바꾸지 않습니다.
요청한 모든 구성요소에 출처·`asOf`·`unavailable`을 포함합니다.

| 결과 | 의미 | 다음 행동 |
| --- | --- | --- |
| `success` | 요청한 모든 구성요소에 기준 시각을 확인한 사용 가능한 행이 있음 | 담당자가 내용과 한계를 검토한 후 명시적으로 채택 |
| `partial` | 일부 사용 가능한 행은 있으나 요청한 다른 부분이 비었거나 누락됨 | 누락을 표시하고 보완. 완전 성공이나 최초 성공으로 집계하지 않음 |
| `empty` | 사용 가능한 행이 없고 최소 하나의 유효한 빈 응답은 있음. 다른 오류가 있다면 함께 표시 | 잘못된 입력/검색 범위 여부 확인. 오류와 혼동하지 않음 |
| `error` | 모든 요청 구성요소가 사용할 수 없음 | 키·입력·기관 장애·시간 초과를 구분해 재시도/지원 요청 |

예: 사업자 상태는 조회됐지만 요청한 지역 코드 입력을 확인할 수 없으면 `partial`입니다.
지역 정보를 요청하지 않은 상태 단독 작업은 상태 결과만으로 판단합니다.
응답에 행이 있어도 키·기준 시각·최신성 문제가 있으면 해당 부분을 사용 가능한 것으로 표시하지 않습니다.
상태 코드 자체는 기관 뜻대로 해석하며, 폐업 상태도 정상 조회 결과일 수 있습니다.

## 오프라인 증거와 지원 경계

[오프라인 증거 모음](https://github.com/bridger-kr/bridger-docs/tree/main/docs/gtm)은 두 번들 총 50개 중 이 번들 25개의 합성 정규화 예시를 포함합니다.
실제 사업자번호·주소·키·기관 응답은 포함하지 않고 네 가지 결과와 누락 처리만 검증합니다.
원본 제공 기관 스키마 호환성, 실행 가능성, 사용자 채택률을 증명하지 않습니다.

담당자는 입력과 권리, 지원 창구와 예상 비용을 확인하고 장애 시 원문 입력을 분석 도구에 복사하지 않습니다.
시점이 없거나 지원되지 않는 주소는 빈칸 대신 누락 사유를 표시합니다.
문의할 때에는 도구명·시각·정제된 오류 코드만 공유하고 개인정보는 제외하세요.
