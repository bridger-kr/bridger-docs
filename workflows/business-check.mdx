<Warning>휴폐업 상태는 거래 승인 결론이나 신뢰도 점수가 아닙니다. 신용·사기·실소유자·신원 검증과 상세 주소 검증은 제공하지 않으며, 최종 판단은 담당자가 합니다.</Warning>

## 1. 이런 질문으로 시작

거래처 등록을 반복 처리하는 담당자가 신규 거래처를 검토할 때 이렇게 물어봅니다.

- "123-45-67890 사업자등록번호 영업 중인지 확인해 줘."
- "아래 번호 세 개 휴폐업 상태 확인해 줘: 123-45-67890, 987-65-43210, 555-22-10101."
- "여러 거래처 번호를 한 번에 상태 확인해 줘."

앱(Claude · ChatGPT)에 [Bridger를 연결](/guides/claude)한 새 대화에서 물어보면,
등록된 도구 목록에서 맞는 도구를 골라 호출합니다.

## 2. 어떤 도구가 사용되는가

질문에 따라 아래 도구가 호출됩니다. 프리셋·도구 목록은
[행정·민원 카탈로그](/presets/civil)에서 확인하세요.

| 프리셋 | 도구 | 용도 |
| --- | --- | --- |
| `civil/business-registration` | `getBusinessRegistrationStatus` | 사업자등록번호로 휴폐업 상태·과세유형 조회. 번호는 목록(`businessRegistrationNumbers`)으로 전달하며 1회 최대 100건 |
| `civil/business-registration` | `validateBusinessRegistration` | 대표자·개업일까지 대조하는 진위확인. 기존 사업자 정보 확인 위젯이 이 도구를 사용합니다 |
| `resolve_location` | 지역 정규화 | 한국 지역명 또는 좌표를 행정 코드·기상 격자로 변환. [지역 입력 방식](/concepts/korean-data) 참고 |

`resolve_location`은 상세 주소 검증기가 아닙니다. 도로명·건물·우편 주소 검증은
지원하지 않고, 동명 지역은 어떤 지역인지 구분해서 질문하면 처리됩니다.

개발 환경에서는 [첫 도구 호출](/getting-started/first-tool)처럼 `tools/list` ·
`tools/call`로 직접 호출할 수 있습니다. 제공기관별 사용량 한도는 카탈로그 표
(사업자등록 상태조회는 1회 100건·일 100만 건)를 따릅니다.

## 3. 결과를 어떻게 읽는가

| 항목 | 읽는 법 |
| --- | --- |
| `businessStatusName` / `businessStatusCode` | 휴폐업 상태. "정상", "폐업" 등 국세청 등록 상태가 그대로 돌아오며, "폐업"도 조회 실패가 아니라 정상 조회 결과입니다 |
| `taxTypeName` / `taxTypeCode` | 과세유형(일반과세자, 간이과세자 등) |
| `closedOn` | 폐업일 — 폐업 건에만 표시됩니다 |
| 진위확인 결과 | 상태조회와 별개입니다. 상태조회는 등록 상태를, 진위확인은 대표자·개업일 대조를 확인합니다 |

상태 조회는 국세청 등록 정보의 "지금 등록 상태"를 확인하는 것입니다.
거래 승인 근거나 신용 판단으로 확장해서 읽지 않고, 필요한 판단은 담당자가
추가 확인 후 내립니다.

## 이 작업의 경계

- 사업자등록번호는 담당자가 적법하게 보유한 경우에만 입력합니다. 번호·질의 내용은 공개 예시나 문서에 다시 남기지 않습니다.
- 답변이 비어 있거나 오류면 먼저 입력한 번호를 확인하고, 입력이 맞는데도 반복되면 키·API 사용 설정 문제와 조회 문제를 구분해서 문의합니다.
- 제공기관은 국세청([공공데이터포털 15081808](https://www.data.go.kr/data/15081808/openapi.do))입니다. 등록 정보에는 제공기관의 갱신 주기가 반영되므로, 제공 데이터 기준시각이 지났으면 판단 전에 다시 조회하세요.
